# 通用项目文件与目录规范

本规范约束“文件出现时应放在哪里”，不要求项目预先创建一棵完整目录树。没有业务源码、测试或 OpenSpec 变更时，对应目录不存在是正常状态。新增文件时先按用途、归属和生命周期分类，再采用项目技术栈已经约定的具体路径。

本规范适用于开发者和 AI 工具。它约束新增文件、生成输出和新建一级目录；现有文件的迁移、运行路径和外部资料清理必须通过单独的迁移方案确认。语言、框架、数据库和部署工具的细节由项目级规范或技术附录补充。

## 创建文件前

1. **确认用途**：这是生产源码、测试、稳定文档、可复用工具、生成文件，还是一次性产物？
2. **确认归属**：模块专用内容就近放入模块；跨模块说明放入 `docs/`；跨模块工具放入 `scripts/` 或项目已有的 `tools/`。
3. **确认权威位置**：同一用途只保留一个权威入口。更新已有说明，避免创建“最新版”“补充版”副本。
4. **确认工具约定**：Maven、Gradle、Python、npm、IDE、CI 和 AI 工具的规定位置优先于通用示例。
5. **检查影响**：新增或移动后检查引用、生成脚本、忽略规则、发布流程和是否包含真实数据。

无法直接归类时，选择最接近的现有用途目录并在变更说明中记录理由；不要因为根目录方便就把文件放在那里。新增一级目录时，补充根 README 或最近的入口文档中的职责说明。

## 按用途选择位置

下表描述目录语义。除根入口和工具规定的位置外，目录都按需创建。

| 用途 | 首选位置 | 规则 |
| --- | --- | --- |
| 项目入口和元数据 | 仓库根目录 | 放 `README.md`、许可证、贡献/安全说明、顶层构建入口和必要的工具配置。不要放临时文档、日志或构建产物。 |
| 生产源码 | 现有模块目录下的技术栈标准源码目录，例如 `src/`、`backend/`、`packages/<name>/` | 遵循语言和框架的默认布局；多模块项目按模块归属，不能为套用示例而重排已有源码。 |
| 测试代码 | 与源码对应的 `tests/`、`test/`、`src/**/__tests__/` 或技术栈标准测试目录 | 测试应能追溯到被测模块；不要把可重复测试放入临时目录。 |
| 测试夹具和脱敏样本 | 测试目录下的 `resources/`、`fixtures/` 或 `testdata/` | 只提交合成、脱敏且规模可控的资料；真实业务数据和大型文件放外部资料目录。 |
| 稳定文档 | `docs/` | 按读者和用途分类，避免把长期说明、临时计划和实验输出混在一起。 |
| API 和协议说明 | `docs/api/` 或对应模块文档目录 | 说明调用方可见的契约，链接规格、生成文档或兼容说明。 |
| 架构与技术决策 | `docs/architecture/`、`docs/adr/` 或既有决策目录 | 只保留仍有效的系统说明；图的可维护源文件和文档就近维护。 |
| 开发、调试和测试指南 | `docs/development/` | 记录命令、环境、配置方式和必要前置条件。 |
| 部署、运维和恢复 | `docs/operations/`、`deploy/`、`infra/` 或项目既有入口 | 手册和配置归属保持一致；密钥和本机配置不写入文档。 |
| 调研和资料比较 | `docs/research/` | 记录结论、来源和日期；下载缓存与原始大附件放外部目录。 |
| 代码或设计审查记录 | `docs/reviews/` | 记录审查对象、结论、关联提交或 change。 |
| 历史方案 | `docs/archive/` | 标明历史状态并指向当前有效说明；不要用 archive 代替删除无价值文件。 |
| 项目和团队规范 | `docs/conventions/` 或工具规定的项目级入口 | 每类规范保留一个权威文件；`AGENTS.md`、`CLAUDE.md` 等只引用规范，不复制正文。 |
| 规格驱动开发产物 | `openspec/`（启用 OpenSpec 时） | 由 OpenSpec 管理 proposal、specs、design、tasks、验证和归档；不要手工创建不符合工具约定的变更目录。 |
| 可复用开发和维护脚本 | `scripts/<用途>/`、`tools/` 或模块内 `scripts/` | 写明输入、输出、副作用和是否可重复执行；一次性探针不要伪装成通用工具。 |
| 部署入口和代理配置 | 根目录既有 Compose/工作流文件、`deploy/`、`infra/` 或 `nginx/` | 保持相对路径和调用方约定；迁移入口时同步更新调用方。 |
| AI 技能、Agent 指令和工具配置 | 工具规定的位置，例如 `.agents/skills/`、`.claude/skills/`、`.codex/` | 采用工具官方发现规则；技能入口使用工具要求的 `SKILL.md` 或等价格式。 |
| AI 提示词、工具 schema 和评测 | 所属 AI 模块下的 `prompts/`、`schemas/`、`evals/` 或项目既有目录 | 版本化的模板、schema、评测定义和少量脱敏样例可入库；运行输出和大数据集放外部目录。 |
| UI 设计系统和产品资源 | `design-system/`、前端模块的 `assets/` 或项目现有设计工具目录 | 保持设计源文件和生成资源的关系，避免建立重复的设计规范入口。 |
| 第三方运行时依赖 | `third_party/<name>/`、语言生态的 `vendor/` 或工具规定目录 | 只保留实际构建/运行需要的内容，并记录来源、版本和许可证。仅供阅读的源码放外部 `reference-projects/`。 |
| 生成代码和构建产物 | 工具规定的路径，例如 `generated/`、`build/`、`dist/`、`target/` | 标明生成方式；除非项目明确发布，否则加入 Git 忽略。生成文件不能手工维护。 |
| 一次性脚本、日志、截图和导出结果 | 外部 `runs/<日期>/<任务>/`，或项目既有且被忽略的临时目录 | 同一任务共用一个目录；有长期价值的结论另写正式文档。 |
| 模型、媒体和大型数据集 | 外部 `fixtures/`、`runtime/`、`archives/` 等受控目录 | 通过配置或参数读取；仓库只保留小型脱敏样本、索引和调用说明。 |
| 密钥、转储和本机备份 | Git 忽略的本机配置、密钥系统或受控外部备份目录 | 示例配置只含占位值；真实凭证、数据库转储和本机路径不能进入普通文档或提交。 |

## 根目录职责

根目录只保留项目入口、应用模块、正式资料和工具发现所必需的文件。常见入口包括 `README.md`、许可证、`AGENTS.md`/`CLAUDE.md`、`package.json`、`pyproject.toml`、`pom.xml`、`build.gradle`、顶层 Compose/CI 配置和 `.gitignore`。

新增功能计划、验收报告、临时脚本、截图、音视频、压缩包和历史构建不要继续堆在根目录。根目录已经存在的旧文件不构成继续新增同类文件的理由。

## 外部资料与本机路径

真实数据、大型附件、下载包、历史备份和一次性运行结果原则上放在仓库外，并由项目入口记录如何配置位置。构建产物和依赖缓存沿用工具默认位置与忽略规则。具体外部目录由项目决定，规范不能把某一台机器的绝对路径写成通用要求。

新脚本必须显式接收输入和输出路径，不得把当前用户名、工作树或盘符写死。需要在工作树内产生的小型临时文件必须放入已有的、被 Git 忽略的任务子目录，并说明保留周期；不要自动清理或跨盘迁移旧内容。

## AI 项目补充规则

- 可复用的 Skill、Agent 指令和工具 schema 按工具发现规则存放；是否启用并行 Agent 属于执行策略，不改变文件归属。
- Prompt、模型参数、评测标准和数据处理代码属于可审查的项目资产，应版本化并记录适用模型、输入约束和变更原因。
- 运行轨迹、模型响应、真实用户内容和大评测集按敏感级别放外部受控目录；提交前确认脱敏和许可证。
- 评测输出应能追溯到代码、Prompt、模型版本和数据版本；最终结论写入 `docs/research/` 或 `docs/reviews/`。

## 新增文件完成检查

- 用途、模块归属和生命周期已经明确；
- 已检查现有同用途目录和权威入口；
- 路径符合项目技术栈和工具的约定；
- 生成物、缓存、临时文件、真实数据和密钥没有误提交；
- 新增一级目录已记录职责，文档链接和生成脚本可达；
- Git diff 只包含本次需要保留的文件。

## 依据

本规范按职责归类，具体子目录是项目可采用的约定，并非所有工具共同强制的标准。工具默认布局参考以下官方说明；复制本文件到目标项目时无需连带复制研究材料。

- [GitHub About repositories](https://docs.github.com/en/repositories/creating-and-managing-repositories/about-repositories)
- [Maven standard directory layout](https://maven.apache.org/guides/introduction/introduction-to-the-standard-directory-layout.html)
- [Gradle Java Plugin](https://docs.gradle.org/current/userguide/java_plugin.html)
- [Python src layout](https://packaging.python.org/en/latest/discussions/src-layout-vs-flat-layout/)
- [npm package.json](https://docs.npmjs.com/cli/v11/configuring-npm/package-json)
