# AI/LLM 后端扩展规则

> 使用模型、RAG、语音、图像、Agent 或模型工具调用时读取。本附录在通用安全、隐私和外部调用规则之上增加 AI 特有控制。

## 一、数据与信任边界

- prompt、原始媒体、转写、模型响应、向量和评测数据按敏感数据管理。
- 用户内容、检索文档、工具返回和模型输出均视为不可信输入。
- 发送给模型或供应商前执行数据最小化、必要脱敏和租户范围检查。
- 不在日志记录完整 prompt、转写或模型响应；排障采样必须受权限、脱敏和保留期控制。
- 供应商的数据使用、训练、地域、保留和删除条款记录在项目画像或合规文档。

## 二、Prompt Injection 与工具调用

- 系统指令与用户内容结构化隔离，不能依赖自然语言声明建立安全边界。
- 检索文档中的指令不自动获得系统权限，外部内容不能改变工具白名单。
- 工具、URL、文件路径、SQL、命令和目标资源由服务端授权与结构化 schema 约束。
- 高风险工具使用最小权限、参数白名单、调用次数、金额/资源上限和人工确认。
- 模型不能自行扩大身份、租户、文件或网络访问范围。
- 工具结果回传模型前过滤密钥、令牌和无关敏感信息。

## 三、输出验证

- 结构化输出校验 schema、枚举、长度、数值范围、关联 ID 和证据引用。
- 解析失败进入明确失败或受控重试路径，不使用宽松字符串截取伪造成功。
- 模型输出进入 HTML、SQL、路径、模板或命令前执行目标上下文的安全编码或白名单校验。
- RAG 在检索阶段强制租户和权限过滤，不先跨租户召回再在展示层隐藏。
- 引用和 evidence 必须能回溯到调用时实际可见的来源，不能信任模型自报标识。

## 四、成本与可靠性

- 设置输入/输出 token、媒体时长、并发、频率、重试、租户预算和总 deadline。
- 记录模型、供应商、prompt 版本、用量、耗时和结果类别，不记录不必要的正文。
- 重试只覆盖明确的瞬时失败；模型内容不符合业务要求通常不是无界重试理由。
- 降级模型或缓存结果必须满足数据权限、质量和时效契约。
- GPU、模型服务和供应商并发使用跨实例 bulkhead，不只限制单进程。

## 五、发布与治理

- 模型结果进入发布、知识库、资金、权限或外部动作前，按风险设置人工审核和版本锁。
- 保存足够的输入版本、模型版本、prompt 版本、证据和审核记录以支持追溯。
- 模型或 prompt 升级使用固定评测集验证正确性、安全、越权、注入、泄漏和成本回归。
- 建立停止开关、配额下调和供应商故障切换流程，并验证其不会绕过权限。
- 自动化决策明确申诉、人工复核和纠错路径。

## 六、测试

- 覆盖直接和间接 prompt injection、工具越权、跨租户检索、敏感信息提取和超长输入。
- 覆盖非法 JSON、未知枚举、伪造 evidence、超范围分数和迟到响应。
- 使用代表性失败和对抗样本，不只测试理想 prompt。
- 对非确定输出采用性质、schema、评分阈值和人工抽检，不以完整字符串相等作为唯一断言。
