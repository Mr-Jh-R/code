# Python 后端附录

> 仅在目标模块使用 Python 时读取，并遵循 [通用后端核心](../core.md)。语言风格参考 PEP 8、PEP 257 和 Google Python Style Guide；以下响应契约是本规范包的团队约定，不是 Python 官方强制标准。使用 FastAPI 时另读 [框架附录](../frameworks/fastapi.md)，其他框架按同一契约接入其异常机制。

## 一、版本、环境与工程

- Python 版本以项目 `requires-python`、运行镜像和实际工具链为准，测试覆盖受支持版本；不要为示例语法无条件升级运行时。
- 使用项目隔离环境与既有包管理器，明确可复现的安装、运行和验证命令。应用固定可部署依赖，库声明兼容范围并测试；不强迫两者采用相同锁定策略。
- 优先在 `pyproject.toml` 集中配置构建、依赖和工具，已有合法项目布局可保留。可发布包按项目选择 `src/` 或 flat layout，不通过修改 `sys.path` 掩盖打包与导入错误。
- 模块按业务能力组织，可用函数或类表达服务。只有确有替换、测试或跨模块契约需要时引入 `Protocol`/ABC，不机械照搬 Java 的 Service 接口与 Impl 双层结构。
- 导入模块时不执行网络请求、数据库迁移或启动后台任务；资源初始化交给显式入口/应用生命周期，脚本入口使用 main guard。

## 二、命名、导入与文档

- 模块、函数、参数和变量使用 `snake_case`，类使用 `PascalCase`，常量使用 `UPPER_CASE`。语法糖命名为 `throw_if`，不照搬 Java 的 `throwIf`。
- 显式导入并清理无用项，避免 `from x import *`；同名类型用清晰的 `as` 别名区分。导入分组、行宽和换行由项目 formatter/linter 统一，不能混用多套互相冲突的风格要求。
- 公共模块、非平凡公共函数与类用 docstring 说明用途、关键参数、返回、异常及副作用；不逐行复述实现，不要求为自解释的小函数制造长文档。
- 新增代码遵循项目已有 PEP/Google/NumPy 文档风格。已有命名或公开字段变更需要兼容方案，不能把风格修正当成无影响重命名。

## 三、类型与模型

- 公共接口、稳定业务边界和复杂集合提供类型注解，逐步限制 `Any` 与无结构字典；忽略类型检查要局部、有理由且可复审。
- `dataclass` 适合内部结构，`TypedDict` 描述固定字典，Pydantic 等校验模型用于采用该工具的外部边界。类型提示、`TypedDict`、`cast()` 不执行运行时输入校验。
- 请求模型只包含允许调用方提交的字段，响应模型只包含可公开字段；ORM 实体、内部凭据和供应商对象不直接成为公共响应。
- 必填、可空、缺省及部分更新的“未传/传 null”分别定义，不用 `None` 同时表达所有状态。敏感写入使用显式字段白名单。
- 默认参数不使用共享可变 list/dict/set；需要新容器时在函数内创建，dataclass 使用 `default_factory`。类属性的可变值也要明确共享语义。
- 缺失判断使用 `is None`；`0`、`False`、空串和空集合不自动视为失败。`assert` 可用于测试/内部不变量，不用于用户输入、权限或需要生产保证的校验。
- 金额使用 `Decimal` 或最小货币单位整数，明确舍入；时间点使用有时区语义的 datetime，输入输出格式及单位遵循项目契约。

## 四、成功响应、业务异常与语法糖

采用本附录的新建普通 JSON 业务接口统一使用 `code/message/data`：成功为整数 **`code=0`**，失败为登记的非零整数。返回类型声明为 `BaseResponse[UserVO]` 等具体泛型；响应工具使用 `success(data)` 函数即可，无需建立全是静态方法的工具类。

```json
{"code": 0, "message": "ok", "data": {"id": 1, "name": "示例用户"}}
```

```json
{"code": 40400, "message": "资源不存在", "data": null, "requestId": "服务端关联标识"}
```

- 成功 `data` 可以是 `0`、`false`、空列表或 `null`；调用方不能用 data 的真假值判断成功。错误体固定 `data=null`，请求标识可放响应头并按项目需要同步响应体。
- `code=0` 只用于成功；非零码通过自定义业务异常或框架异常进入全局异常处理器，路由不临时拼接错误 dict，也不捕获所有异常后伪装成功。
- 业务异常继承 `Exception`，保存登记的错误定义。对外消息来自安全模板；内部诊断通过异常链和受控日志保留，不能把原始异常、请求体、密码或 SQL 拼进 message。
- `throw_if(condition, error_code)` 在条件为真时抛出 `BusinessException`，为假时不产生动作。条件应表达简单卫语句，不能以一串语法糖替代复杂领域校验或依赖框架的字段校验。
- 异常的 HTTP 映射由 Web 适配层负责，业务层不依赖请求对象或某个框架的异常类。错误码登记在项目唯一入口，不在业务代码散落数字。
- **HTTP 状态保留真实含义**：创建用 201，异步受理用 202；参数/认证/授权/冲突使用对应 4xx，未知错误使用 500。HTTP 成功还要结合业务码判断，禁止把全部失败包装成 HTTP 200。
- 文件下载、SSE、WebSocket、重定向、HEAD 和 204 等按协议处理，不强制添加普通 JSON 包装。后台任务和已开始输出的流发生失败时，使用其任务/流协议报告，不能改写已发送的 HTTP 响应。
- 已发布的其他响应结构先登记兼容策略，不在规范安装时自动破坏客户端；错误码编号可沿用项目已发布约定，但成功 `0` 与非零失败的语义明确。本附录不强迫非 HTTP 脚本输出响应包装。

参考码表（项目新增具体错误在独立号段登记）：

| 场景 | HTTP | 默认 code |
| --- | --- | --- |
| 参数或业务前置条件非法 | 400 | 40000 |
| 未认证 / 无权访问 | 401 / 403 | 40100 / 40300 |
| 不存在 / 方法不支持 | 404 / 405 | 40400 / 40500 |
| 版本或状态冲突 | 409 | 40900 |
| 请求校验失败 | 422 | 42200 |
| 限流 | 429 | 42900 |
| 未知错误 / 上游错误 / 不可用 / 上游超时 | 500 / 502 / 503 / 504 | 50000 / 50200 / 50300 / 50400 |

参考实现为 HTTP 协议错误保留 `状态码 × 100` 的编号（400–599），如 410 对应 41000；具体业务错误在不冲突的号段单独登记，不能根据任意业务码反推 HTTP 状态。示例错误模型使用正整数；已有负数错误码的项目按兼容策略调整模型约束。

可运行的 [FastAPI 参考实现](../examples/python/fastapi_contract.py) 演示泛型成功响应、错误模型、枚举、自定义异常、`throw_if` 和集中异常转换；只是适配示例，不要求所有 Python 项目安装 FastAPI。

## 五、异常、资源与日志

- 捕获能够处理的具体异常，边界翻译使用 `raise BusinessException(...) from exc` 保留原因；不要用裸 `except:` 或吞掉 `BaseException`、取消、退出信号。
- `with` / `async with` 管理文件、连接、锁和客户端，`finally` 用于清理，不在其中 return 掩盖异常。
- 服务日志使用项目 logging 门面；CLI 的正常输出可用 stdout。按责任边界记录一次错误，控制日志大小、敏感内容与字段；`logger.exception` 也可能输出秘密，需脱敏策略。
- API 未知异常返回固定安全消息，记录请求标识与可定位的堆栈。响应校验/序列化失败属于服务端问题，不归为用户请求错误。
- 日志、重试、审计和事务回滚不能只依赖前端错误消息；吞掉异常会改变事务结果，失败路径须有测试。

## 六、异步与并发

- `async def` 不会自动卸载阻塞 I/O；使用兼容的异步客户端或受控线程卸载，CPU 密集工作按负载选择进程/独立 worker，限制队列与下游并发。
- 任务有明确所有者、超时、取消和收敛路径；目标版本支持时可使用 `TaskGroup`。不要创建丢失引用、无人 await 或无人观测异常的后台任务。
- 清理后通常重新抛出 `CancelledError`；不吞取消信号、不把客户端断开自动转成一次新的重试。
- 不把 GIL 当成业务不变量的同步保证；线程/任务共享状态、连接和 ORM Session 遵循其线程安全约束。连接数和容量不会因协程或线程数增加而扩大。

## 七、验证与工具

- 沿用项目的一套 formatter/linter、一个主要类型检查器和测试框架。新项目可选 Ruff、mypy 或 Pyright、pytest；已有 Black/isort/Pylint/unittest 不为本附录全部替换。
- 若项目使用 Ruff，运行 `ruff format --check .` 和 `ruff check .`；类型检查运行选定工具的实际项目配置，测试按项目命令执行。Ruff 不替代类型检查或业务测试，命令以项目已安装工具为准。
- 单测不依赖网络和共享业务数据；数据库事务、序列化、异步取消和框架异常映射用相应集成测试证明。依赖、测试数据与可控时间按风险隔离。
- 响应测试同时断言 HTTP、整数 code、字段结构与脱敏；覆盖成功的假值、业务异常、请求校验、未知异常、错误响应头以及不包装的响应。应用测试验证生产异常策略，不能只证明语法糖能抛异常。
