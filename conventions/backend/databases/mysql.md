# MySQL 数据库附录

> 仅在项目画像声明使用 MySQL 时读取。版本、存储引擎、字符集和隔离级别以目标环境为准。

## 一、Schema

- 默认使用 InnoDB；字符集使用 `utf8mb4`，排序规则由语言、大小写和升级兼容需求决定。
- 表有主键；主键策略由写入模式、分片、索引局部性和外部暴露需求决定，不强制统一雪花 ID。
- 必填、唯一、引用、范围和合法状态使用目标 MySQL 版本实际支持的约束表达。
- 金额使用定点数或最小货币单位整数，明确精度和舍入。
- 时间列明确表达时间点或本地日历时间，并统一时区转换；不使用无时区约定的字符串。
- JSON 只承载确实变化的扩展数据；频繁查询字段使用普通列或经过验证的生成列/索引。
- 软删除必须定义唯一性、默认查询、恢复、审计和最终清理语义，不作为所有表的机械默认值。

## 二、索引与查询

- 查询明确列出需要的字段；稳定业务查询不使用无边界的 `SELECT *`，避免字段漂移和不必要的数据读取。
- SQL 值使用参数化接口；表名、列名、排序字段和表达式只来自服务端白名单，不把用户输入直接拼入 SQL。

- 索引对应真实查询、关联和排序，使用 `EXPLAIN` 或目标版本支持的 `EXPLAIN ANALYZE` 验证。
- 复合索引遵循最左前缀能力，但列顺序由等值、范围、排序和选择率共同决定。
- 外键引用列根据关联和父记录更新/删除路径评估索引。
- 避免重复、包含关系明显但无额外收益的索引；评估写放大和 buffer pool 占用。
- 深分页使用 keyset/cursor，批量查询、导出和删除设置上限与分批策略。
- 不使用“单表固定行数必须分库分表”作为硬规则，基于数据量、工作集、延迟、写入和运维能力决策。
- 业务唯一性必须由唯一约束或唯一索引兜底；应用层预检查不能替代数据库约束。
- 表、字段和索引命名遵循项目画像记录的统一约定；常见 `pk_`、`uk_`、`idx_` 前缀可以采用，但不把某一套命名强制到所有数据库。

## 三、事务与并发

- 明确项目实际隔离级别以及一致性读、锁定读的差异。
- 检查后插入的唯一性最终由唯一约束保证，并正确处理 duplicate key。
- 多行加锁保持稳定顺序，事务尽量短，避免用户交互和远程调用。
- 对死锁和锁等待超时只在幂等、有限预算下重试，并记录指标。
- 使用 `INSERT ... ON DUPLICATE KEY UPDATE` 时确认受影响行数、触发器和更新时间语义。

## 四、迁移

- 迁移前核对目标版本的 online/inplace/instant DDL 能力和限制，不能只依赖语法接受。
- 大表字段、索引和字符集变更评估锁、重建空间、复制延迟和回滚方式。
- 使用 expand-migrate-contract 保持新旧应用兼容，数据回填限速并可断点恢复。
- 迁移工具中的幂等语句不静默接受同名但定义不同的对象。

## 五、运行配置

- 配置连接获取、语句、事务和锁等待时限，避免默认无限等待。
- 连接池总量按数据库预算除以应用实例和运维余量计算。
- 监控慢查询、锁等待、死锁、buffer pool、连接使用、复制延迟和磁盘增长。
- 备份恢复在与生产版本相近的环境实际演练。
