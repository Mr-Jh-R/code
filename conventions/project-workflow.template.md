# 项目工作流约定模板

复制为目标项目的 `docs/conventions/project-workflow.md`，或把必要字段合入已有项目约定。只填写项目实际采用的选项，删除不适用项；已有后端画像、发布手册或 CI 定义通过路径引用，不重复维护。

这些字段是供人和 AI 阅读的约定，不是某个工具自动加载的配置格式。机器绝对路径、凭证和临时端口放在本机配置中，仓库只说明如何取得。

## 采用来源与入口

| 项目事实 | 填写内容 |
| --- | --- |
| 规范包来源 | 仓库 URL 与实际采用的 release tag / commit SHA；采用未提交草稿时明确注明 |
| 文件归类规范 | 安装后的本地规范路径 |
| Git 协作规范 | 安装后的本地规范路径 |
| Agent 入口 | 实际使用的 AGENTS.md、CLAUDE.md 或等价入口 |
| 已安装技能 | SDD、API 文档等实际 Skill 路径；只列已安装项 |
| 技术规范 | 前端入口、后端项目画像或其他技术栈规则的实际路径 |

## 开发与整合

| 项目事实 | 填写内容 |
| --- | --- |
| 集成分支 | 汇集完整开发成果的分支；维护多个版本时逐项说明用途 |
| 功能分支与隔离 | 项目命名规则，哪些任务需要独立 worktree |
| 提交与合入 | PR/评审、分支保护、允许的合入策略和必要检查 |
| 任务与待整合登记 | 已有 issue、PR、OpenSpec 或登记文档入口；有并行依赖时填写 |
| 权威验证入口 | CI 或已有开发指南路径，及需要补充的本地命令 |
| SDD 默认模式 | 默认 simple；项目需要时填写 standard；用户本次选择优先 |
| Superpowers / 委派 | 是否允许以及适用场景；simple 模式遵循 SDD Skill 的关闭规则 |

实时分支状态和提交 SHA 以 Git 为准。只有不能直接从仓库推导的约定需要持续维护在这里。

## API 文档（有接口时）

| 项目事实 | 填写内容 |
| --- | --- |
| 读者与文档入口 | 各类调用方的主文档路径，或已有 API 文档索引 |
| 默认契约基线 | 对应的集成开发版本；分支预览和已发布版本的标注方式 |
| 契约来源 | OpenAPI/其他协议定义、导出方法和验证版本的方式 |
| 本地运行 | 已有开发指南；只读核对或无法启动时可用的导出快照/测试 |
| 客户端生成 | 项目已有生成命令与输出路径；未使用生成器时删除此项 |
| 文档语言与格式 | 面向读者的语言、现有模板和文档检查命令 |

## 发布与例外（按需填写）

- 发布方式、不可变版本命名和回滚入口：引用现有运维手册。
- 维护分支或紧急修复的回合入方向及负责角色：填写实际约定。
- 与通用规则不同的项目选择：记录适用范围、原因和保障；临时例外注明收敛条件。

完成条件：开发者和 AI 能找到集成基线、适用规范、验证命令与契约入口，无需从分支名、端口或历史对话猜测。
