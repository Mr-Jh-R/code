# 本地规范版本的选择与维护

本 Skill 的流程版本和编码规范的版本分别管理。完整规范保存在版本库，不依赖目标项目预先复制规范，也不在每次检查时访问 GitHub。

## 本地命令

用当前 Skill 实际路径下的 `scripts/standards_store.py`，不要从其他同名 Skill 或旧克隆找脚本。需要 Python 3.10+；安装快照和查询上游还需要 Git。下列 `<脚本>`、`<目录>`、`<版本ID>` 是需要替换的占位符。

```text
python <脚本> list
python <脚本> resolve
python <脚本> resolve --version <版本ID>
python <脚本> verify --version <版本ID>
```

默认版本库为 `$CODEX_HOME/standards/code`，未设变量时为 `~/.codex/standards/code`。其他工具或项目级安装可在子命令前传 `--store <目录>`；同次检查保持同一目录。`list/resolve/verify/read-plan` 只读且离线，返回 JSON。退出码：0 成功，2 需要用户选择，1 执行或完整性错误。

`list` 列出实际完整性校验通过的本地版本、源码仓库和 SHA；损坏版本单列为 invalid。哈希用于发现本地修改和缺失，不是发布者签名或防篡改证明。只写了目录名、VERSION 或 Git tag 不能证明快照已经安装。

## 选择一次，保持固定

1. 用户本次明确来源/版本优先，其次沿用当前任务已确认的版本，再使用项目明确固定版本，最后使用用户保存的默认版本。会话接续到另一个项目或用户变更选择时重新解析。
2. `resolve` 可传 `--version`、`--session-version`、`--project-version`，其顺序同上；自动读取的只有版本库中的用户默认，不擅自解析或修改任意项目 Markdown。项目声明的 source 必须匹配本规范仓库，commit 如有声明也必须与快照一致。
3. 未选择时，展示 `list` 的本地选项：版本 ID、发布版/开发快照、SHA、主要区别。优先推荐本地最高稳定 tag，但即使只有一个版本也让首次使用者确认，不以超时当作选择。固定 tag 中没有的新规则不能混入本次检查。
4. 已指定但未安装或损坏时，明确说明原因，提供其余已验证本地版本和“获取指定版本”选项；不静默切换。没有版本时提供安装入口，不能以“Skill 没有 React 规范”结束，也不能编造本地选项。
5. 当前任务选择通常只记在对话中。用户明确说“设为以后默认”时才执行 `default --version <版本ID>`；不因安装新版本修改默认。

项目自己的规范可作为明确的“项目本地规则”来源，需逐一确认入口和内容，不声称它等于某个官方快照。有项目固定版本而用户选择新版时，将发现分为“当前项目违规”和“新版升级差距”；项目补充规则/例外单列，冲突按项目优先级解释。项目副本与其声明 tag 内容不同应比较差异，不能仅凭画像版本号宣布一致。

## 安装与更新（仅在用户要求时）

默认源为 `https://github.com/Mr-Jh-R/code.git`。安装只写版本库，不修改业务项目、其他 Skill 或全局工具配置。脚本支持本规范源；用户指定其他规范来源时按其明确版本读取，不将其伪装为本源快照。

### 从本地已知来源安装

```text
python <脚本> install --repo <规范仓库目录> --ref v2.4.0
python <脚本> install --repo <规范仓库目录> --ref <完整40位提交SHA>
```

使用精确稳定 tag 或完整 SHA，不接受浮动分支。脚本检查 origin，直接导出提交中的 `conventions/`、VERSION、LICENSE、CHANGELOG；不会执行源仓库代码，也不会复制未提交修改。tag 与 VERSION 必须匹配。快照目录是 `versions/vX.Y.Z` 或 `versions/snapshot-<完整SHA>`，清单记录来源、提交、种类和每个文件的 SHA256。

开发快照的 VERSION 可能仍是上一发布版本；展示时始终使用 snapshot ID，不能因此称为该发布版。同 ID 不允许覆盖不同提交或不同内容，安装新版本保留旧版。

### 查询和获取上游

用户要求“检查更新”时运行 `updates`，只查询源仓库稳定版本标签，不下载、不改默认。远端标签列表不是本地已安装清单。用户要求最新正式版时，按语义版本排序选最高稳定 tag；预发布和开发 main 不混入稳定版。

用户选择未安装的 tag 后，在项目外的独立临时目录初始化 Git 仓库，设置上述 origin，fetch 精确的 `refs/tags/<tag>` 到同名本地 tag；核对解析出的提交与查询时的 SHA 一致，再运行 `install`。获取 main 只在明确选择开发版时进行：获取远端 main，解析为完整 SHA 后安装；检查期间不再跟随 main 更新。不要在目标业务仓库 fetch/checkout 规范代码。

网络失败时保留本地版本，并说明“无法确认上游最新”；继续使用另一版本需要用户已有选择或明确改选。通过本地仓库安装时，清单证明导出内容和声明来源；是否与当前远端一致需要更新操作另行核对。

## 首次安装与回退

用户级安装复制完整 Skill 目录到工具已发现的用户技能位置，再用上述脚本安装所选规范。项目级安装同样可用，并可显式配置版本库路径；无需同时装两套同名 Skill。检测到多份入口时说明本次实际使用的 Skill 路径与规范 root，不能混读。

回退只需选择保留的旧版本；不移动标签、不覆盖版本文件、不清理其他版本。更新 Skill 本身应先备份已有完整目录，保留用户定制；Skill 的 `installation.json`（若安装器提供）仅记录流程来源，不代替规范快照的 manifest。普通检查不升级 Skill。
