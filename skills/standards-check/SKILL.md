# 规范检查与本地版本选择

本 Skill 负责选择并实际读取规范后检查代码，不仅提供审查流程。默认单 Agent、只读业务代码；修复、联网查询更新、安装或更换默认版本分别依据用户授权。流程更新与编码规范版本是两件事，不把项目源码自动迁移到新规则。

## 1. 确认动作与版本

先完整读取 [本地版本指引](references/local-versions.md)，使用本 Skill 内的 [版本脚本](scripts/standards_store.py) 执行 `list` 或 `resolve`；普通检查不联网。Python/Git 或脚本不可用时报告实际缺口，不虚构版本。

- 优先级为：用户本次明确选择 → 当前任务已确认选择 → 项目固定版本 → 用户保存的默认。项目 source/commit 同时核对；其他来源不得仅凭相同版本号匹配。
- 没有选择时，展示已验证的本地版本选项（发布版/开发快照、SHA 和差异），推荐稳定发布版，让用户选择。工具支持选项交互就提供选项，否则简洁列出选项后询问；不默认提交选择，不反复询问已确认的版本。
- 指定版本缺失或损坏时报告并给出可用选项/安装方式；不能静默降级。普通检查期间不下载，不将旧克隆、任意同名文件或变化中的 main 当成规范基线。
- 用户要求检查更新时才联网列出远端稳定 tag；用户选择安装后固定 SHA 导出本地快照。用户明确要求开发版时固定 main 的当时 SHA，标为开发快照。安装不设置默认；只有明确要求才保存长期默认。

完成条件：本次规范来源、版本 ID、SHA、本地路径已确定，或者返回有实际本地选项的待选择状态。只有用户选择后才开展依赖该版本的规范判定。

## 2. 路由并读取正文

完整读取 [技术栈阅读指引](references/reading-guide.md)。核对目标项目入口、Git 基线、任务差异和构建文件，选择实际技术栈规则；项目无需预先复制规范正文。

从确定的本地快照读取前端/后端入口和相应规范正文。React 必须继续读取 React 规范；Python 等没有专用附录时读取跨语言核心、独立选择数据库/AI 等附录，并沿用项目生态配置。不能把 Java 约束套到其他语言，不能只读取本 Skill 就称“没有 React 规范”。所选版本要求完整读取的文件分段读完，不以搜索片段代替。

项目补充规则与例外单列；项目本地副本与其声明版本不同要检查差异。用户选择新通用版本时，区分当前项目违规和升级差距，不自动覆盖项目规范。声明一次“本次 Skill 路径；通用规范来源/版本/SHA/root；项目补充入口”，整次检查固定该基线。

完成条件：受影响技术与章节的实际正文已读取，规则冲突、版本差异和缺失附录已明确。

## 3. 检查与修复

- 仅核对指定文件、提交或任务差异；包含适用的暂存、未暂存、未跟踪内容及必要调用方，混合任务先划定归属。用户要求全项目时才扩展全仓。
- 按所选质量门禁与项目命令执行检查。低风险文档只运行相关检查，代码按影响选择测试，权限/事务/数据库增加专项证据；不能把“轻量”当成跳过必需项的理由。
- 优先复用与源码、规则版本、配置、依赖和环境仍一致的结果；切换规范版本后重新判断证据有效性。优先 check 模式，不运行业务写操作、部署或格式化写回来完成只读审查。
- 实现后单独核对差异和自动工具未覆盖的规则。每项发现附规则来源/章节、文件位置和影响，区分确定违规、待确认与改进建议；目录缺失和正则命中不直接等于违规。
- 已授权修复时只改本任务范围内确定问题，保留其他改动，重查受影响项。不删除测试、放宽规则制造通过，不无关重构；同一阻塞反复出现且无新证据时报告，不无限重试。

完成条件：适用检查标为通过、失败、执行异常、未执行或不适用（说明理由）；必需项未满足且没有项目允许的有效例外时不宣布验收通过。规范快照校验通过不表示代码合规。

## 4. 简短反馈

说明所用规范版本、已读正文范围、实际命令/证据、问题和未覆盖部分。无发现时只说明本次范围未发现违规，不保证零缺陷。不强制生成报告；检查通过不代表已提交、集成或发布。原任务和 SDD 可复用有效结果，不再做一次相同审查。
