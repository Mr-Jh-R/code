# 规范专项检查

针对已指定的改动或项目范围给出有依据的规范检查结果。默认单 Agent、只读，不创建分支、不提交发布、不修改规则，也不默认生成报告文件。用户已授权修复时可在明确范围内修复复查；不重复请求同一授权。

## 1. 定位范围与规则

- 读取项目入口、Git 状态、现有工作流约定及任务目标。识别用户指定的文件、提交、PR 基线或全项目范围；仅说“检查这次改动”时检查该任务差异，不扩大到全仓。
- 核对基线 SHA、目标 SHA 及适用的未提交/未跟踪文件。混合工作区先区分归属；差异不足以判断时阅读必要调用方、配置、契约和测试。范围缺失且无法推导时只询问阻塞该检查的信息。
- 通过项目入口找到已安装的通用质量门禁和活动技术规范；本规范包默认安装位置为 `docs/conventions/quality-gates.md`，路径以项目实际引用为准。按门禁的风险分级、结果状态、证据复用与放行规则执行。
- 没有通用门禁副本时沿用项目已有检查规则，报告缺少的约定；不自动安装文件。没有权威编码规范时可报告明确正确性问题和建议，不能把个人风格称为“违反项目规范”。

完成条件：对象、基线、适用规则、检查命令及只读/修复权限明确，只加载相关材料。

## 2. 自动检查与单独审查

- 从项目构建脚本、CI 或约定找到可执行命令，优先复用仍对应当前源码、配置、依赖和环境的结果。缺失命令记为未配置/未执行，不虚构命令或通过结果。
- 文档改动只运行相关文档检查；普通代码运行相关模块检查；权限、事务、数据库或跨模块改动增加必要专项证据。项目硬性门禁仍适用，不以“轻量”为由跳过。
- 默认用 check 模式；不要启动自动格式化、部署或写入共享业务数据。命令副作用超出权限时，说明执行缺口并继续其余独立核对。
- 在实现之外单独核对差异：按适用规范检查契约、权限、数据/事务、依赖、模型与组件复用等受影响内容。工具输出只是证据之一，不把 regex 命中或目录缺失直接当成违规。
- 区分确定违规、待确认和改进建议。每项附规范路径/章节、代码文件/行、影响与修复方向；同时标明是本次新增问题还是相关历史问题。

完成条件：本次适用规则已核对，检查分别记为通过、失败、执行异常、未执行或不适用；无证据项不算通过。

## 3. 处理与复查

- 只读审查完成后输出发现和限制，不改源文件、配置、暂存区或平台设置。只读模式允许项目检查产生正常隔离缓存，不能借此运行业务写操作。
- 已授权修复时，仅修本任务范围内已证实的问题并保留其他改动；业务意图仍不明确时列出具体差异，不擅自选择会改变契约的答案。
- 修复后重新检查受影响的行为和规则；范围扩大时增加对应检查。代码改变后不沿用已失效结果；没有新变化或疑点时不重复跑完整审查。
- 必需项失败、执行异常或未执行时，明确尚未通过；只使用项目政策允许且已获有权确认的例外。不得通过删测试或放宽规范制造绿灯。
- 同一阻塞反复出现且无新证据时，停止无效修复循环，报告阻塞条件与下一步；不自动启动子代理或重复审查任务。

## 4. 简短反馈

输出检查范围与基线、问题、实际命令/结果及影响交付的缺口。问题可用“规则依据 → 文件位置 → 影响 → 建议”表示；已修复时简述修复与复查结果。

无发现时说明本次范围和未验证部分，不保证绝对合规。只有适用必需项通过或已有有效例外时才给出可交付结论；规范检查通过不表示已提交、已合并或已发布。结果供原任务和 SDD 复用，不要求再做一次相同审查。
