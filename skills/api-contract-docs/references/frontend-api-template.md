# 调用方接口文档模板

沿用已有文档的目录层级。以下结构用于保证单个接口可以独立查阅，不要求每次新增空白小节。

## 文档开头

说明面向哪个调用方、覆盖哪些模块、适用版本/环境、Base URL、认证方式和示例值的性质。常见返回包装、公共分页约定和通用错误集中说明一次。一个模块不同接口的分页规则不同则在各自条目明确列出。

默认以项目确认的集成开发基线为准；未集成接口单独标注为对应分支的开发预览。用户指定工作区、提交或发布版本时以指定目标为准，已核实的部署差异另记。

接口索引按业务模块列“方法、路径、用途、可用状态、锚点”。文件名不使用“最新版”“补充版”建立重复主文档。

## 单个接口的结构

1. **用途和方法路径**：一句话说明调用目的，是否只查询或产生变更。路径与Base URL的关系保持一致。
2. **入参表**：字段、位置、类型、必填、默认/限制、含义。嵌套字段用 `items[].id` 表示；互斥、成对和条件必填写在对应字段旁。
3. **请求示例**：可复制的方法、路径、Content-Type和合法请求体。需要从前一接口取得的ID、版本、预览号明确指出。
4. **响应示例与字段表**：使用真实结构的脱敏或合成示例；标注单位、null、缺省和枚举。列表成功空结果与请求失败区分。
5. **必要操作规则**：说明排序、完整覆盖、版本冲突、轮询或一次性限制等会影响调用正确性的行为。
6. **错误处理**：HTTP状态、业务码、触发条件、前端动作。通用错误链接公共章节，本接口特有分支就地解释。

## 合成示例：分页读取任务

下面只展示排版风格，不代表任何项目已有此接口或这些限制。实际文档应由目标项目证据替换。

`GET /tasks`：分页读取任务列表。

| 字段 | 位置 | 类型 | 必填 | 默认/限制 | 含义 |
| --- | --- | --- | --- | --- | --- |
| pageNo | query | integer | 否 | 默认1，至少1 | 从1开始的页码 |
| pageSize | query | integer | 否 | 默认20，1～100 | 每页条数 |

请求：

```http
GET /tasks?pageNo=1&pageSize=20
```

成功响应（合成数据）：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "records": [{ "id": 101, "name": "示例任务", "status": "PROCESSING" }],
    "total": 1,
    "pageNo": 1,
    "pageSize": 20
  }
}
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| data.records | object[] | 当前页任务，无匹配时为空数组 |
| data.records[].id | integer | 任务ID，用于读取详情 |
| data.records[].name | string | 任务名称 |
| data.records[].status | string | PROCESSING处理中、COMPLETED已完成 |
| data.total | integer | 符合条件的总条数 |
| data.pageNo / pageSize | integer | 实际使用的分页参数 |

## 需要按接口选择的分支

- **文件上传**：示例用 multipart/form-data，并明确 `file`、其他表单字段和数组编码；浏览器FormData的boundary由客户端生成。
- **文件下载**：列出Content-Type、Content-Disposition、缓存/文件名约定；说明错误是否仍为JSON以及如何识别。
- **异步操作**：返回任务/版本标识、状态查询入口和可结束轮询的状态；“已接收”只解释接收结果。
- **批量操作**：上限、空数组和重复ID规则、原子或逐项结果、计数含义；给出部分失败响应。
- **乐观版本控制**：字段来自哪个查询，冲突如何刷新，用户已有编辑如何处理；示例保持版本前后关联。
- **兼容结构**：分别说明新旧字段名、JSON字符串与对象、适用版本和推荐读取方式，避免一个示例混用两种契约。
- **未接入/不可用**：区别于正常空结果，给出可显示的状态与下一步操作。

仅保留有助于调用的说明。正文不需要解释为何使用某张表、事务如何加锁、模型算法如何打分；如果公开字段属于诊断用途，说明字段含义和是否需要展示即可。
